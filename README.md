# 记住你宇哥 · macOS 与 Windows

原名 BiliFetch。软件显示名和图标已更新；为兼容旧版在线更新，发布包名和应用数据目录继续使用 BiliFetch 标识；Windows 主程序改为“记住你宇哥.exe”，保留 BiliFetch.exe 作为旧版兼容入口。无需迁移已有设置、登录状态或未完成任务。

> Windows 10/11 x64 便携版也已提供，源码位于 `Windows/`，构建脚本为
> `scripts/build-windows.sh`。成品解压后运行 `记住你宇哥.exe`，详细说明见
> `Windows/README.md`。Windows 1.1.0 起支持 SHA-256 校验的应用内升级，
> 1.1.1 起完整内置所有下载组件。

粘贴 B 站视频、合集链接，或抖音视频分享链接及整段分享文字，先预览标题与封面，再下载到本地。下载内核使用 yt-dlp，可选 aria2 多连接加速，FFmpeg 自动合并高画质音视频。

## 启动使用声明

macOS 1.5.16 / Build 26、Windows 1.1.10 起，每次启动都显示使用声明。只有手动点击“我已知晓”才进入主界面并恢复既有任务；关闭窗口或退出不视为确认，不保存“下次不再提示”。若上次异常退出留下临时代理，网络恢复仍可在确认前执行。

## 视频号播放捕获（测试阶段）

macOS 1.5.15 / Build 25、Windows 1.1.9 增加「视频号捕获」入口。开启后在电脑微信重新打开并播放目标视频，确认作品进入捕获列表，再勾选加入下载。只确认当前实际播放的作品，预加载、隐藏或身份不明的画面不会自动收录。

Windows 1.1.11 起使用原生 WinINet 读取、设置和恢复代理，无外部代理及默认自动检测状态可以直接开启。首次启用需要确认本机证书和临时代理；已有 HTTP/HTTPS 代理会按每台电脑的实际配置接续，关闭捕获恢复原设置。现阶段不支持 PAC 自动代理和需要账号密码的代理。下载沿用既有画质、进度、续传与校验；未加入去水印或后台账号。实现及验证边界见 `Shared/WeChatCapture/README.md`。

2026-09-23 已在 Mac 微信 4.1.9 实测正常播放、只捕获当前作品、最高明示画质下载及音视频完整解码；Windows 真机流程尚待验证。本功能保持测试阶段，不保证所有微信版本和作品均可用。

## 抖音视频分享

- macOS 1.5.14 / Build 24、Windows 1.1.8 接入抖音视频分享解析。输入框支持 `v.douyin.com` 短链接、视频页面链接及整段分享文案；同一链接重复出现会合并，包含不同作品的输入会要求一次粘贴一条。
- 两端使用同一份内置解析器，无需登录抖音、导入 Cookie 或额外安装 Python，也不依赖第三方解析服务。先读取抖音移动端公开作品信息，备用接口和分享页作为回退；始终核对作品 ID，避免下载推荐视频。
- 登录设置只用于 B 站；即使已选择浏览器，也不会为抖音读取浏览器账号。免登录方式不能保证所有作品可用，私密、已删除、受限作品或平台接口变化会明确报错。
- 此入口用于单条视频，暂不支持作者主页、直播、图集或批量抓取。媒体地址保持页面原样，没有增加去水印处理。
- **验证边界（2026-09-23）**：用户提供的作品 `7688293605819075875` 已在本机使用内置下载器免登录下载完成，FFprobe 确认含 HEVC 视频和 AAC 音频；接口本次提供的最高分辨率为 1280×720。纯链接和整段分享文字共用两端测试样例。Windows 仍未做真机运行、安装及下载实测；单个成功样例不代表所有抖音作品均可下载。

macOS 与 Windows 正式包均完整内置 yt-dlp、FFmpeg、FFprobe 和 aria2。启动后自动检测并直接使用，不需要用户下载安装环境；只有组件被安全软件删除或损坏时才显示“修复组件”。

更新地址随正式包内置，不在软件界面显示，也不需要用户填写。软件每次启动只检查一次版本；没有新版或网络暂时不可用时保持安静，发现新版才询问用户。新版客户端会优先下载与当前版本精确匹配的文件级增量包，找不到增量包或增量校验、应用失败时自动回退完整 ZIP；下载过程仍优先使用内置 aria2，多连接不可用时自动切回标准下载。

更新清单会保留两个平台各自的版本历史。发现新版时，客户端按本机版本筛选并依次显示尚未安装的每一版说明，例如从 macOS 1.5.8 升到 1.5.11 会显示 1.5.9、1.5.10 和 1.5.11。发布流程会继承上一版清单并自动追加本次说明；旧客户端仍能读取累计说明。

安装更新时只允许启动一个替换程序；点击“退出并升级”后界面会立即进入安装状态并禁用重复操作。若系统没有响应正常退出请求，应用会自动结束旧进程，让安装器完成替换；替换失败时仍会恢复备份。

主界面采用紧凑布局：保存路径和下载操作位于链接输入框下方，高级设置从右上角打开。顶部操作区会像冻结表头一样固定，解析后的分集卡片在下方独立滚动，浏览长合集时仍可随时暂停或调整设置。

活动分集会显示旋转状态图标、呼吸边框和进度条流光；高速模式直接从 aria2 的本机会话汇总实时字节数与速度，并依次显示视频流、音频流和合并阶段，让排队、连接、下载和卡死状态更容易区分。分片视频会汇总全部活动、等待和已完成分片，不会只在结束时跳到 100%。

## 合集下载流程

1. 粘贴合集、系列、播放列表或多 P 视频链接。
2. 在“下载范围”中选择“整个合集”（可识别的合集链接也可使用智能模式）。
3. 粘贴链接后会自动获取合集列表；也可以点击“重新获取”。
4. 查看所有标题、缩略图和时长，通过每项复选框选择需要的视频（默认全选）。
5. 下载时按 `[序号] 标题 [视频ID].mp4` 自动命名，并保存到以合集标题命名的文件夹。

合集下载采用并行队列：不会按 FLV、MP4 等容器格式筛选条目，每一集都会在下载前独立解析。单集失败会记录并继续下一集；切换到标准引擎后可以立即重试失败项目，已完成项目不会重复下载。

## 断点续传与电源策略

- yt-dlp 与 aria2 都会保留断点文件；暂停、临时断网或应用重新打开后，可从已有进度继续。
- 下载中的链接、选中分集、保存目录、画质、引擎和并发数会保存为未完成任务。再次打开软件后会自动解析列表并续传未完成分集。
- 正常下载时会阻止 macOS 因空闲而自动睡眠，但不会阻止用户主动合盖。
- 合盖睡眠前会安全暂停并保存断点；唤醒后等待网络恢复，再自动继续。用户手动暂停的任务不会被系统唤醒流程擅自恢复。
- 临时失败会保留断点并自动重试；达到三次重试上限后才删除该分集的不完整文件，并要求重新解析链接。
- 全部任务结束后，仅在确认对应最终视频存在且非空时，清理与它匹配的 `.part` 和 `.aria2` 遗留文件。
- 完成判定会排除 `.f数字.mp4/.m4a` 等 yt-dlp 中间流，并通过 FFprobe 同时确认最终文件含视频轨和音频轨；未合并文件会保留并进入自动重试。
- 合并容器固定为内置 FFmpeg 支持的 MP4；B站的 AVC/HEVC 视频与 AAC 音频会直接封装，避免误选未打包的 MKV 封装器而反复失败。

## B站账号与画质

- 高级选项中可使用 B 站官方扫码登录接口。本软件不读取或保存账号、密码和验证码。
- 登录后会把 B 站 Cookie 保存到当前用户的 BiliFetch 应用数据目录，并以仅当前用户可读写的权限交给 yt-dlp。
- 无论是否登录，画质初始值都是“当前可用最高画质”；登录只会扩展账号本身有权访问的画质范围。
- 仍可选择 Safari、Chrome、Edge 或 Firefox Cookie 作为备用方式。

## 双平台在线更新

macOS 1.5.7 与 Windows 1.1.0 起使用同一份 `update.json`，但分别比较各自的平台版本号并下载对应 ZIP。GitHub Actions 发布前会同时测试两端；任一端失败都不会创建 Release。

macOS 1.5.10 与 Windows 1.1.3 是首批具备增量安装能力的版本。旧客户端升级到这两个版本时仍需下载一次完整包；从它们升级到后续版本时，发布流程会自动比较上一版完整包，只打包改变和删除的应用文件，并对发生少量变化的大文件生成块级二进制补丁。增量包不可用时无需用户处理，客户端会自动下载完整包兜底。

首次建仓、发布新版和日常维护步骤见 [`GITHUB_RELEASE_GUIDE.md`](GITHUB_RELEASE_GUIDE.md)。早于上述版本的客户端没有升级模块，需要由用户手动更新一次；之后即可在软件内完成升级。

## 边界

- 仅用于你有权保存的内容。
- 不绕过会员、付费、DRM、私密内容或其他访问控制。
- aria2 高速模式让媒体 CDN 直连，但合集元数据解析仍沿用系统网络设置；需要时可以切换到标准 yt-dlp。
